# Task 4：思考题

## 1. Make 和简单的 build.sh 有什么区别？

### `build.sh`每次运行都会从头到尾执行全部的gcc命令，不管有没有文件改动，都会跑一遍，`全部重新编译`。  
### `Make`可以先检查文件的时间戳，只有文件被修改过，才会重新编译。没有被修改过的不会编译，可以`节省大量时间`。同时可以维护依赖关系，头文件被修改，则会自动重新编译所有用到这个头的源码。也可以多核并行编译多个文件，且某一步编译失败就会停止，`大大提高了效率`。

## 2. CMake 是编译器吗？
### CMake 本身`不是编译器`，它只是构建系统生成工具，不负责将C代码翻译成机器码。

执行 `cmake --build build` 时，最终是谁在编译 C 源文件？
### `gcc(GNU C 编译器)`。`cmake --build build`调用底层构建工具（在linux环境下是make）
> ### 具体流程：CMake生成Makefile→cmake --build调用make→make调用gcc完成编译链接

## 3. 为什么不希望每次都重新编译所有 `.c` 文件？

- ### `耗费大量时间`:全部编译相当于做了很多无用功，虽然一样可以得到成功，但是无疑耗费大量时间，尤其是`面对大型项目`，劣势格外突出，时间就是金钱。更体现出了`加入工作室的优势`，有很多学长学姐的经验，避免自己一条一条地去试，浪费宝贵时间。只修改了1个，说明其余49个源码保持不变，它们编译出来的.o文件完全不动，不需要重复生成做很多不必要的工作。增量编译只编译被修改以及依赖它的文件，可以`提高开发效率`。
